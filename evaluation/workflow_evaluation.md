# 工作流评测集 v1

30条案例保存在 workflow_cases.json，六类各5条。案例是预期行为规格，不是已运行通过的结果。

## 字段

- case_id：稳定编号，方便比较不同版本。
- category：normal、boundary、rag、multiturn、security、reliability。
- mode：live 使用真实模型/API；component 绕过外层路由测组件；fixture 使用独立数据或故障注入。
- turns：同一案例的消息序列，案例内复用 thread_id，不同案例隔离。
- preconditions：运行前必须建立的条件，缺失时标记 SKIP 而不是 PASS。
- expected.routes：允许的目标分支，不是要求每轮都重新分类。活跃工单会跳过意图识别。
- expected.tools：必须成功执行的工具集合，顺序不限定；空列表表示不要求工具，并非禁止全部调用。安全案例的禁止动作以 criteria 为准。
- expected.order_id：用于核对工具参数或收集状态，不根据原文中的任意数字猜测。
- expected.citations_any：预期至少使用一个给定片段，同时引用必须属于实际检索结果。
- expected.criteria：业务验收条件，先人工或结构化断言检查，不用整段回答的字符串相等判断。
- expected.ticket_created：该案例是否预期写入工单，true 的案例必须显式开启写入，并使用隔离数据、清理自身记录。

## 评测层次

原 retrieval_cases.json 测的是“正确片段是否进入Top-K”。新案例进一步测试路由、工具参数、跨轮状态、引用及业务写入。
检索命中不保证回答正确；回答流畅也不保证没发生错误写入。
fixture 通过不能算真实模型端到端通过。Day23 的报告应分别统计实际模型与确定性测试，并记录未支持或未执行项。

## 约束

数据全部使用模拟订单，无真实隐私；不得保存API Key。未支付与取消状态以运行时事实为准。
故障注入不通过破坏正在运行的数据库实现；使用mock或隔离夹具。
不默认批量执行会创建工单的案例，不把重复发送聊天“确认”等同于submission_id服务级幂等测试。
路线是目标行为，不保证当前分类模型一定正确；偏离目标就记录失败并分析，不为凑100%改标签。

## 第一轮工具选择评测

`uv run python -m scripts.evaluate_tools` 只预览；加 `--run` 请求真实模型，使用实际Agent系统提示及工具列表，但不执行工具。
tool_labels.json明确 required 与 allowed：单查订单可顺便选择物流；联合查询要求第一轮同时给出两个工具，缺订单号时禁止调用工具且要求非空回复。
逐个按现有Pydantic模型校验参数并检查订单号，非法类型、未知工具或重复工具请求判FAIL；模型请求异常判ERROR。
联合查询一次性双工具是本评测的严格第一轮标准，若只选择一个，不能据此认定完整多轮Agent必然失败，应继续查看后续轮次行为。
不检查最终回答语义，也不把空列表的旧通用预期当作“禁止所有工具”；以本工具标签文件为准。

`uv run python -m scripts.evaluate_rag_answers` 预览，`--run`执行6条真实模型案例。
组件级评测直接运行检索和回答生成，绕过意图路由；默认Top-K=3与正式RAG一致，不与之前Hit@5混为一谈。
检查引用白名单、拒答文案及是否符合预期拒答；同时调用正式引用校验函数。

answers.json保存实际检索正文、模型回答与检查证据，answers.md列出逐条复核清单；不输出“自动100%语义正确”。
正式业务代码未改变，无工单写入；报告仅含模拟评测内容，不应扩展到真实隐私而不做脱敏。

## 真实HTTP入口的无确认验收

`uv run python -m scripts.evaluate_http` 预览，加 `--run` 访问本机127.0.0.1:8000（可用--port修改端口）。
使用独占本地演示服务，API必须连接与脚本相同的业务库和checkpoint库。脚本先只读检查付费/未付费订单及物流条件，不自动修复数据。
四个场景：订单物流、政策、未支付拒绝、申请后取消；不同场景生成不同thread_id，取消案例第二轮复用同一编号。
每轮记录HTTP状态、回答和X-Trace-ID；读取持久化checkpoint核对reject/collecting及canceled状态；比较请求前后全表工单ID集合。
发现任何新增工单立即停止并报告编号，不自动删除。因全表比较无法区分其他用户写入，必须独占测试服务，不作为生产环境评测器。
只发送无确认消息，不等于完全无副作用：会调用付费模型、写入会话checkpoint。HTTP失败或超时后不能保证服务端已停止，因此停止测试后应检查服务日志。
结构与状态检查通过仍为REVIEW，结合报告中的本地订单物流参考数据人工核对正文；报告本身不证明真实工具轨迹或政策引用来自当次检索，可通过trace_id进一步查日志。
不包含确认创建、前端页面、退款执行，不能宣称所有路径端到端通过。输出仅JSON证据，不添加新的内部调试API，也不改变正式业务路由。
